Sudah paham kenapa GraphQL dan apa itu schema. Sekarang kita bangun server-nya. Kita pakai Apollo Server — implementasi GraphQL paling populer di Node.js — dengan dataset sederhana (mahasiswa, prodi, nilai) yang disimpan di memori. Setelah ini Anda bisa dengan mudah menggantinya dengan database asli (Postgres, MongoDB).

Capaian Pertemuan Ini

Mahasiswa mampu (1) men-setup Apollo Server, (2) menulis SDL schema, (3) menulis resolver untuk Query & Mutation, (4) menguji API di Apollo Sandbox, dan (5) mengenali masalah N+1 dengan solusi DataLoader.

Anatomi GraphQL Server

Setiap server GraphQL terdiri dari dua hal utama:

  1. Schema — kontrak (SDL) yang mendeskripsikan tipe & operasi yang tersedia.
  2. Resolvers — fungsi yang menjawab "bagaimana mengambil data field X". Satu resolver per field (atau auto-resolve jika field punya nama yang sama dengan property objek).

Definisikan Schema (SDL)
Buat file schema.js berisi semua tipe data, Query, dan Mutation:
schema.js 
export const typeDefs = `#graphql
  type Mahasiswa {
    id: ID!
    nim: String!
    nama: String!
    email: String!
    prodi: Prodi!
    nilai: [Nilai!]!
  }

  type Prodi {
    id: ID!
    nama: String!
    jenjang: String!
    mahasiswa: [Mahasiswa!]!
  }

  type Nilai {
    mataKuliah: String!
    nilai: Float!
  }

  type Query {
    mahasiswa(id: ID!): Mahasiswa
    semuaMahasiswa(prodiId: ID): [Mahasiswa!]!
    prodi(id: ID!): Prodi
  }

  input MahasiswaInput {
    nim: String!
    nama: String!
    email: String!
    prodiId: ID!
  }

  type Mutation {
    daftarMahasiswa(input: MahasiswaInput!): Mahasiswa!
    hapusMahasiswa(id: ID!): Boolean!
  }
`;

4
Tulis Resolvers
Resolver dipetakan persis mengikuti struktur schema. Setiap resolver menerima 4 argumen: (parent, args, context, info). Yang paling sering dipakai: parent (objek di level atas) dan args (argumen yang dikirim klien).
resolvers.js 
import { mahasiswas, prodis, nilais } from './data.js';

let nextId = 4;

export const resolvers = {
  Query: {
    mahasiswa: (_, { id }) => mahasiswas.find(m => m.id === id),
    semuaMahasiswa: (_, { prodiId }) => prodiId
      ? mahasiswas.filter(m => m.prodiId === prodiId)
      : mahasiswas,
    prodi: (_, { id }) => prodis.find(p => p.id === id),
  },

  Mutation: {
    daftarMahasiswa: (_, { input }) => {
      const mhs = { id: String(nextId++), ...input };
      mahasiswas.push(mhs);
      return mhs;
    },
    hapusMahasiswa: (_, { id }) => {
      const idx = mahasiswas.findIndex(m => m.id === id);
      if (idx < 0) return false;
      mahasiswas.splice(idx, 1);
      return true;
    },
  },

  // Resolver untuk field relasi — dipanggil otomatis saat klien minta field tsb
  Mahasiswa: {
    prodi: (parent) => prodis.find(p => p.id === parent.prodiId),
    nilai:  (parent) => nilais.filter(n => n.mahasiswaId === parent.id),
  },
  Prodi: {
    mahasiswa: (parent) => mahasiswas.filter(m => m.prodiId === parent.id),
  },
};
5
Jalankan Apollo Server
index.js 
import { ApolloServer } from '@apollo/server';
import { startStandaloneServer } from '@apollo/server/standalone';
import { typeDefs } from './schema.js';
import { resolvers } from './resolvers.js';

const server = new ApolloServer({ typeDefs, resolvers });

const { url } = await startStandaloneServer(server, {
  listen: { port: 4000 },
});

console.log(`🚀 Server siap di ${url}`);
terminal 
node index.js

Memanggil dari Klien (Tanpa Apollo Client)

GraphQL berjalan di atas HTTP — bisa dipanggil oleh apa pun yang bisa POST JSON:

curl 
curl -X POST http://localhost:4000 \
  -H "Content-Type: application/json" \
  -d '{
    "query": "query($id: ID!) { mahasiswa(id: $id) { nama prodi { nama } } }",
    "variables": { "id": "1" }
  }'
fetch() di Flutter / React / vanilla JS 
const res = await fetch('http://localhost:4000', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    query: `query($id: ID!) {
      mahasiswa(id: $id) { nama prodi { nama } }
    }`,
    variables: { id: '1' },
  }),
});
const { data } = await res.json();

Bonus: N+1 Problem & DataLoader

Saat query semuaMahasiswa { prodi { nama } } dijalankan untuk 100 mahasiswa, resolver Mahasiswa.prodi dipanggil 100 kali. Jika di belakangnya ada query database, itu 101 query: 1 untuk daftar mahasiswa + 100 untuk masing-masing prodi — inilah N+1 problem.

Solusi: DataLoader (oleh Facebook) — mem-batch & men-cache request dalam satu tick event loop. 100 lookup prodi digabung menjadi satu WHERE id IN (...).

prodiLoader.js — DataLoader untuk batch 
import DataLoader from 'dataloader';
import { prodis } from './data.js';

export const prodiLoader = new DataLoader(async (ids) => {
  // 'ids' adalah array semua id yang diminta dalam satu tick
  const found = prodis.filter(p => ids.includes(p.id));
  return ids.map(id => found.find(p => p.id === id));
});

// Pakai di resolver:
Mahasiswa: {
  prodi: (parent) => prodiLoader.load(parent.prodiId),
}

Alternatif di Ekosistem PHP

Tetap ingin di Laravel? Pakai Lighthouse — package GraphQL untuk Laravel. Anda menulis SDL di file .graphql dan menggunakan direktif (@all, @find, @create) yang otomatis terhubung ke Eloquent Model:

graphql/schema.graphql (Laravel + Lighthouse) 
type Query {
  mahasiswa(id: ID! @eq): Mahasiswa @find
  semuaMahasiswa: [Mahasiswa!]! @all
}

type Mutation {
  daftarMahasiswa(
    nim: String! @rules(apply: ["required", "unique:mahasiswas,nim"])
    nama: String!
    email: String! @rules(apply: ["email"])
  ): Mahasiswa! @create
}

type Mahasiswa {
  id: ID!
  nim: String!
  nama: String!
  prodi: Prodi! @belongsTo
  nilai: [Nilai!]! @hasMany
}
Tantangan Take-home

(1) Tambah Mutation updateNilai untuk mengubah nilai. (2) Pasang @apollo/server di belakang Express dan tambahkan middleware autentikasi (Authorization: Bearer). (3) Implementasi DataLoader untuk field Mahasiswa.nilai agar tidak N+1.

Cek Pemahaman Anda
1. Apa peran resolver di server GraphQL?
Menyatakan kontrak tipe data
Fungsi yang menentukan bagaimana mengambil data tiap field
Memvalidasi input dari klien
2. Mengapa Mahasiswa.prodi ditulis sebagai resolver terpisah, bukan ditempel saja di Query?
Agar prodi hanya di-load jika klien benar-benar memintanya
Agar query lebih cepat dieksekusi
Karena spec GraphQL mewajibkan demikian
3. N+1 problem di GraphQL paling tepat diatasi dengan ...
Menonaktifkan resolver field-level
DataLoader yang mem-batch & cache lookup
Mengaktifkan HTTP caching

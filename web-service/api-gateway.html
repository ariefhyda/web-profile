Bayangkan aplikasi mobile harus tahu URL 12 microservice yang berbeda — auth, profile, catalog, cart, payment, shipping, dan seterusnya. Setiap kali ada service baru atau pindah datacenter, semua klien harus rilis update. Mimpi buruk. Solusinya adalah API Gateway: satu pintu tunggal yang menyembunyikan kompleksitas internal sistem dari dunia luar.

Capaian Pertemuan Ini

Mahasiswa mampu (1) menjelaskan peran API Gateway, (2) merancang routing & rate limiting, (3) memahami service discovery (client vs server-side), (4) memilih strategi load balancing, dan (5) mengenali konsep GraphQL Federation.

Tanggung Jawab API Gateway

🚏
Routing
/api/users/* → User Service
/api/orders/* → Order Service
🔐
Authentication
Validasi JWT/API Key sekali di gateway, bukan di tiap service.
🚦
Rate Limiting
Batasi 100 req/menit per user/IP untuk cegah abuse.
💾
Caching
Cache response GET yang jarang berubah → kurangi beban service.
📊
Logging & Metrics
Satu tempat terpusat untuk request log, response time, error rate.
🔄
Transformation
Aggregate response, REST→gRPC, ubah format header.
🔒
SSL Termination
HTTPS dihandle gateway; backend pakai HTTP internal yang ringan.
⚖️
Load Balancing
Distribusi request ke instance service yang banyak.

Tools Populer

  1. Kong — Open-source, berbasis Nginx + Lua, plugin ecosystem besar. Pilihan populer di Kubernetes.
  2. Tyk — Open-source, ditulis di Go. Punya UI manajemen yang baik & analytics.
  3. NGINX / NGINX Plus — Reverse proxy klasik. Powerful tapi konfigurasi cukup low-level.
  4. Traefik — Modern, native integrasi Docker & Kubernetes, auto-discovery service.
  5. AWS API Gateway — Managed service AWS, terintegrasi dengan Lambda & IAM.
  6. Apollo Router / Hasura — GraphQL-native gateway dengan kemampuan federation.

Pola: Backend-for-Frontend (BFF)

Variasi gateway: satu gateway khusus per jenis klien. BFF Mobile mengagregasi data dengan field minimal & format ringkas; BFF Web mengirim lebih banyak field; BFF Partner pakai kontrak yang berbeda total.

🍽️
Analogi: Pelayan untuk Tiap Meja

Restoran besar tidak punya satu pelayan untuk semua tamu — ada pelayan khusus meja keluarga (porsi besar, ramah anak), meja bisnis (cepat, formal), dan meja VIP (paling teliti). BFF = pelayan yang dikhususkan untuk satu segmen klien.

Konfigurasi Sederhana — Contoh Kong

kong.yaml — declarative config 
_format_version: "3.0"
services:
  - name: user-service
    url: http://user-svc.internal:8001
    routes:
      - name: users-route
        paths: ["/api/users"]
    plugins:
      - name: jwt
      - name: rate-limiting
        config:
          minute: 60
          policy: local

  - name: order-service
    url: http://order-svc.internal:8002
    routes:
      - name: orders-route
        paths: ["/api/orders"]
    plugins:
      - name: jwt
      - name: cors
      - name: request-transformer
        config:
          add:
            headers: ["X-Source: gateway"]

Service Discovery — Bagaimana Service Menemukan Service Lain?

Di lingkungan modern, IP & port service berubah-ubah (container restart, autoscaling). Anda tidak bisa hard-code http://10.0.5.21:8080 di kode. Service Discovery adalah sistem registri "siapa berada di mana".

Dua Pola Discovery

PolaCara KerjaContoh
Client-side Klien tanya ke registry "siapa Order Service?" lalu pilih sendiri instance mana & panggil langsung. Netflix Eureka, HashiCorp Consul
Server-side Klien tinggal panggil http://order-svc; load balancer di tengah yang routing ke instance sehat. Kubernetes Service DNS, AWS ELB

Service Discovery di Kubernetes — Native & Sederhana

Kubernetes punya service discovery built-in. Setiap Service resource otomatis dapat DNS name. Anda hanya butuh nama, bukan IP:

order-service.yaml 
apiVersion: v1
kind: Service
metadata:
  name: order-svc      # → DNS: order-svc.default.svc.cluster.local
spec:
  selector:
    app: order
  ports:
    - port: 80
      targetPort: 3000

# Dari service lain, cukup panggil:
# http://order-svc/orders/123

Load Balancing Strategies

Round Robin
Bergiliran ke instance 1, 2, 3, 1, 2, 3, ... Sederhana, default banyak LB.
Least Connections
Pilih instance dengan koneksi aktif paling sedikit. Cocok untuk request panjang/streaming.
Weighted
Beri bobot per instance (8GB RAM dapat 2× traffic dari 4GB). Berguna untuk hardware heterogen.
IP Hash / Sticky
Hash IP klien → selalu route ke instance yang sama. Untuk legacy app yang butuh session affinity.

GraphQL sebagai API Gateway — Federation

Apollo Federation memungkinkan beberapa GraphQL service (subgraph) digabung jadi satu supergraph tunggal yang dilihat klien. Tiap tim memiliki schema-nya sendiri; gateway yang menyatukan.

Schema Users Service (subgraph) 
type User @key(fields: "id") {
  id: ID!
  nama: String!
  email: String!
}

type Query {
  user(id: ID!): User
}
Schema Orders Service (subgraph) — extend User 
type Order {
  id: ID!
  total: Float!
  user: User!
}

# Service ini memperluas User dengan field 'orders'
extend type User @key(fields: "id") {
  id: ID! @external
  orders: [Order!]!
}

Klien dapat mengirim satu query { user(id: 1) { nama orders { total } } } — gateway memecahnya ke dua subgraph, menggabung hasilnya, mengembalikan ke klien sebagai satu response.

Rate Limiting — Strategi Umum

  1. Fixed Window — Hitung request dalam jendela waktu tetap (mis. per menit). Sederhana tapi rawan "burst" di pergantian jendela.
  2. Sliding Window — Jendela bergulir; lebih akurat tapi butuh memori lebih.
  3. Token Bucket — Bucket terisi token X per detik; tiap request konsumsi 1 token. Boleh "menabung" untuk burst.
  4. Leaky Bucket — Request dimasukkan antrian dengan kapasitas maks; diproses dengan rate konstan.
Gateway Bisa Menjadi Single Point of Failure

Karena semua traffic lewat gateway, kalau gateway down, seluruh sistem unreachable. Jalankan gateway dengan minimal 2 instance di belakang load balancer L4, monitor dengan health-check ketat, dan hindari logika berat di gateway (delegasikan ke service backend).

Aturan Emas

Gateway boleh: routing, auth, rate limit, transformasi response. Gateway tidak boleh: logika bisnis. Begitu Anda mulai menulis aturan diskon atau menghitung pajak di gateway, Anda sedang membuat "monolith baru" yang sulit di-test & diversion-control. Pertahankan gateway tetap "tipis".

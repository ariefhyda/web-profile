Pertemuan 5: Hands-on — Membangun REST API CRUD

Estimasi: 100 Menit
Praktikum
Laravel 11

Video Praktikum: CRUD API

Klik untuk memutar

Setelah memahami prinsip REST, saatnya tangan kotor. Pada praktikum ini kita akan membangun REST API Mahasiswa dari nol menggunakan Laravel — framework PHP yang sudah Anda kenal dari mata kuliah Web Framework. Tujuannya: satu endpoint /api/v1/mahasiswa yang menerima GET POST PUT DELETE dan menyimpan data di MySQL.

Capaian Pertemuan Ini

Mahasiswa mampu (1) memetakan operasi CRUD ke method & URL REST, (2) menggunakan php artisan untuk men-generate model + migration + controller, (3) menulis Route::apiResource, dan (4) menguji endpoint dengan curl/Postman.

Langkah Demi Langkah

1
Buat project Laravel baru
Pastikan PHP 8.2+ dan Composer terpasang. Jalankan perintah berikut di terminal:
terminal 
# 1. Buat project baru
composer create-project laravel/laravel api-kampus
cd api-kampus

# 2. Salin .env.example dan generate APP_KEY
cp .env.example .env
php artisan key:generate

# 3. Konfigurasi koneksi MySQL di .env
#    DB_DATABASE=api_kampus     DB_USERNAME=root     DB_PASSWORD=

# 4. Aktifkan route API (Laravel 11 perlu install:api)
php artisan install:api
2
Generate Model + Migration + Controller sekaligus
Artisan punya shortcut untuk membuat ketiganya dalam satu perintah. Flag --api akan men-generate controller tanpa method create dan edit (karena API tidak butuh form HTML):
terminal 
php artisan make:model Mahasiswa --migration --controller --api --requests
Hasil: app/Models/Mahasiswa.php, database/migrations/xxxx_create_mahasiswas_table.php, app/Http/Controllers/MahasiswaController.php, plus dua Form Request untuk validasi.
3
Definisikan skema tabel di Migration
Buka file migration baru dan isi method up():
database/migrations/xxxx_create_mahasiswas_table.php 
public function up(): void
{
    Schema::create('mahasiswas', function (Blueprint $table) {
        $table->id();
        $table->string('nim', 10)->unique();
        $table->string('nama');
        $table->string('email')->unique();
        $table->string('prodi');
        $table->decimal('ipk', 3, 2)->nullable();
        $table->timestamps();
    });
}
Jalankan migration: php artisan migrate — Laravel akan membuat tabel mahasiswas di MySQL.
4
Setel mass-assignment di Model
Edit app/Models/Mahasiswa.php agar field yang boleh diisi dari API tertulis eksplisit (mencegah mass-assignment vulnerability):
app/Models/Mahasiswa.php 
class Mahasiswa extends Model
{
    use HasFactory;

    protected $fillable = ['nim', 'nama', 'email', 'prodi', 'ipk'];
}
5
Daftarkan route dengan apiResource
Satu baris route resource akan otomatis mendaftarkan 5 endpoint sekaligus (index, store, show, update, destroy):
routes/api.php 
use App\Http\Controllers\MahasiswaController;
use Illuminate\Support\Facades\Route;

Route::prefix('v1')->group(function () {
    Route::apiResource('mahasiswa', MahasiswaController::class);
});
Cek hasil mapping route: php artisan route:list --path=api.
6
Isi Controller dengan 5 method
Edit MahasiswaController.php. Laravel sudah membuat skeleton method-nya — tinggal kita isi:
app/Http/Controllers/MahasiswaController.php 
use App\Models\Mahasiswa;
use Illuminate\Http\Request;

class MahasiswaController extends Controller
{
    // GET /api/v1/mahasiswa
    public function index()
    {
        return Mahasiswa::paginate(10);
    }

    // POST /api/v1/mahasiswa
    public function store(Request $request)
    {
        $data = $request->validate([
            'nim'   => 'required|string|size:8|unique:mahasiswas,nim',
            'nama'  => 'required|string|max:100',
            'email' => 'required|email|unique:mahasiswas,email',
            'prodi' => 'required|string',
            'ipk'   => 'nullable|numeric|between:0,4',
        ]);
        $mhs = Mahasiswa::create($data);
        return response()->json($mhs, 201);
    }

    // GET /api/v1/mahasiswa/{id}
    public function show(Mahasiswa $mahasiswa)
    {
        return $mahasiswa;
    }

    // PUT / PATCH /api/v1/mahasiswa/{id}
    public function update(Request $request, Mahasiswa $mahasiswa)
    {
        $data = $request->validate([
            'nama'  => 'sometimes|string|max:100',
            'email' => 'sometimes|email|unique:mahasiswas,email,'.$mahasiswa->id,
            'prodi' => 'sometimes|string',
            'ipk'   => 'sometimes|numeric|between:0,4',
        ]);
        $mahasiswa->update($data);
        return $mahasiswa;
    }

    // DELETE /api/v1/mahasiswa/{id}
    public function destroy(Mahasiswa $mahasiswa)
    {
        $mahasiswa->delete();
        return response()->noContent(); // 204
    }
}
Catatan: Route Model Binding

Parameter Mahasiswa $mahasiswa di method show / update / destroy adalah route model binding — Laravel otomatis cari mahasiswa berdasarkan ID di URL, dan return 404 Not Found jika tidak ada. Tidak perlu cek manual.

Konvensi Penting yang Sudah Kita Terapkan

  1. Resource jamak — /mahasiswa, satu URI untuk koleksi, satu untuk satuan.
  2. Prefix versi — /v1/ agar kelak bisa rilis /v2/ tanpa merusak klien yang ada.
  3. Status code semantik — 201 untuk create, 204 untuk delete, 422 untuk validasi gagal, 404 otomatis dari model binding.
  4. Validasi sebelum eksekusi — input dicek di Controller sebelum menyentuh database.
  5. Pagination — paginate(10) mencegah satu request mengembalikan jutaan baris.
  6. Mass-assignment guard — hanya field di $fillable yang boleh diisi dari request.

Alternatif Framework — Sintaks Sangat Mirip

Jika tim Anda memilih framework lain, pola pikirnya identik. Ini contoh Express.js (Node.js) untuk endpoint yang sama:

routes/mahasiswa.js — Express 
const express = require('express');
const router = express.Router();
const Mahasiswa = require('../models/Mahasiswa');

router.get('/', async (req, res) => res.json(await Mahasiswa.find()));
router.post('/', async (req, res) => {
    const mhs = await Mahasiswa.create(req.body);
    res.status(201).json(mhs);
});
router.delete('/:id', async (req, res) => {
    await Mahasiswa.findByIdAndDelete(req.params.id);
    res.status(204).end();
});

module.exports = router;
Tantangan Tambahan (Take-home)

(1) Tambahkan filter ?prodi=TI di endpoint index. (2) Tambahkan endpoint nested GET /api/v1/mahasiswa/{id}/nilai yang menampilkan nilai mahasiswa tersebut. (3) Pakai API Resource Laravel agar response keluar dalam format yang konsisten (akan dibahas di Pertemuan 6).

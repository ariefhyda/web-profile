Sebuah API tanpa dokumentasi seperti kamus tanpa indeks — sulit dipakai. Sebuah API tanpa tes seperti pesawat tanpa instrumen — terbang dengan keberuntungan. Pertemuan ini membahas dua tools standar industri yang menyelesaikan kedua kebutuhan tersebut: OpenAPI/Swagger untuk dokumentasi interaktif, dan Postman untuk koleksi request & automated testing.

Capaian Pertemuan Ini

Mahasiswa mampu (1) menyusun spesifikasi OpenAPI 3.0, (2) menampilkan Swagger UI di project Laravel, (3) membuat Postman Collection & Environment, dan (4) menulis tes otomatis sederhana di Postman.

OpenAPI 3.0 — Standar Industri

OpenAPI (sebelumnya bernama Swagger) adalah spesifikasi standar untuk mendeskripsikan REST API dalam format YAML atau JSON. Spesifikasi ini bisa dirender menjadi UI interaktif (Swagger UI, Redoc), dipakai untuk mock server, dan diturunkan ke client SDK.

openapi.yaml 
openapi: 3.0.3
info:
  title: API Akademik Kampus
  version: 1.0.0
  description: Endpoint CRUD data mahasiswa
servers:
  - url: https://api.kampus.ac.id/v1
paths:
  /mahasiswa:
    get:
      summary: Daftar semua mahasiswa
      parameters:
        - name: prodi
          in: query
          schema: { type: string }
      responses:
        '200':
          description: OK
          content:
            application/json:
              schema:
                type: array
                items: { $ref: '#/components/schemas/Mahasiswa' }
    post:
      summary: Buat mahasiswa baru
      requestBody:
        required: true
        content:
          application/json:
            schema: { $ref: '#/components/schemas/MahasiswaInput' }
      responses:
        '201': { description: Created }
        '422': { description: Validation Error }
components:
  schemas:
    Mahasiswa:
      type: object
      properties:
        id:    { type: integer, example: 1 }
        nim:   { type: string,  example: '22550111' }
        nama:  { type: string,  example: 'Siti Aisyah' }
        prodi: { type: string,  example: 'TI' }
        ipk:   { type: number,  example: 3.72 }

Memasang Swagger UI di Laravel

Package l5-swagger (oleh DarkaOnLine) menyederhanakan integrasi. Anda menulis anotasi langsung di Controller, lalu spec OpenAPI di-generate otomatis.

terminal 
composer require "darkaonline/l5-swagger"
php artisan vendor:publish --provider="L5Swagger\L5SwaggerServiceProvider"
app/Http/Controllers/MahasiswaController.php (anotasi) 
/**
 * @OA\Get(
 *     path="/api/v1/mahasiswa",
 *     summary="Daftar semua mahasiswa",
 *     tags={"Mahasiswa"},
 *     @OA\Parameter(name="prodi", in="query", @OA\Schema(type="string")),
 *     @OA\Response(response=200, description="OK")
 * )
 */
public function index() { ... }

Lalu generate & akses dokumentasi:

terminal 
php artisan l5-swagger:generate
# Buka browser ke: http://127.0.0.1:8000/api/documentation

Bagian 2 — Testing dengan Postman

Postman adalah API client paling populer di dunia (50+ juta developer). Selain mengirim request manual, Postman bisa: menyimpan Collection request, mengganti Environment (dev/staging/prod), menjalankan automated tests, dan mengeksekusi semuanya headless via Newman di CI.

Collection — Album Request Anda

Sebuah Collection adalah folder berisi sekumpulan request terkait. Struktur Collection yang baik untuk API kampus:

api-kampus.postman_collection 
📂 API Kampus v1
├── 📂 Auth
│   ├── POST Login
│   └── POST Logout
├── 📂 Mahasiswa
│   ├── GET List mahasiswa
│   ├── POST Create mahasiswa
│   ├── GET Show mahasiswa
│   ├── PATCH Update mahasiswa
│   └── DELETE Delete mahasiswa
└── 📂 Nilai
    ├── GET List nilai per mahasiswa
    └── POST Input nilai

Environment — Variabel per Server

Anda tidak ingin hard-code URL http://127.0.0.1:8000 di setiap request. Environment menyimpan variabel yang berubah per server (lokal, staging, produksi). Buat dua environment: Local dan Production:

Variabel Local Production
base_url http://127.0.0.1:8000/api/v1 https://api.kampus.ac.id/v1
token (diisi setelah login) (diisi setelah login)
admin_email dev@local.test admin@kampus.ac.id

Lalu di Request URL Anda cukup tulis {{base_url}}/mahasiswa. Pindah environment = ganti server.

Automated Test Script di Postman

Setiap request punya tab Tests — JavaScript yang dijalankan setelah response diterima. Postman menyediakan global pm dengan assertion library mirip Mocha/Chai:

Tests untuk: POST Create mahasiswa 
// 1. Status code harus 201
pm.test("Status 201 Created", () => {
    pm.response.to.have.status(201);
});

// 2. Response harus mengandung field id
pm.test("Response punya id", () => {
    const body = pm.response.json();
    pm.expect(body.id).to.be.a('number');
    pm.expect(body.nim).to.eql('22550113');
});

// 3. Simpan id ke environment untuk request berikutnya (chaining)
const body = pm.response.json();
pm.environment.set('last_mhs_id', body.id);

// 4. Response time wajar
pm.test("Response < 500ms", () => {
    pm.expect(pm.response.responseTime).to.be.below(500);
});

Setelah disimpan, jalankan Collection Runner untuk mengeksekusi seluruh request beserta tes-nya secara berurutan. Anda mendapat report: berapa request lewat, berapa gagal, dan di assertion mana.

Pre-request Script — Persiapan Sebelum Kirim

Pre-request Script untuk: GET List mahasiswa 
// Generate timestamp unik untuk request ini
pm.environment.set('timestamp', Date.now());

// Refresh token kalau habis
if (!pm.environment.get('token')) {
    pm.sendRequest({
        url: pm.environment.get('base_url') + '/login',
        method: 'POST',
        body: { mode: 'raw', raw: JSON.stringify({
            email: pm.environment.get('admin_email'),
            password: 'secret'
        }) }
    }, (err, res) => {
        pm.environment.set('token', res.json().token);
    });
}

Newman — Jalankan Collection di Terminal & CI

Newman adalah Postman versi command-line. Cocok untuk dijalankan di GitHub Actions / GitLab CI agar setiap push otomatis menjalankan tes API.

terminal 
# Pasang newman global
npm install -g newman

# Export Collection & Environment dari Postman → simpan sebagai file
# Jalankan suite:
newman run api-kampus.postman_collection.json \
  -e environment-local.json \
  --reporters cli,html \
  --reporter-html-export newman-report.html
.github/workflows/api-test.yml 
name: API Tests
on: [push]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm install -g newman
      - run: newman run tests/api-kampus.json -e tests/env-ci.json
Tips Dokumentasi yang Hidup

Letakkan file openapi.yaml di dalam repo dan otomatis di-generate dari kode (anotasi/decorator). Dokumentasi yang dipisahkan dari kode pasti basi dalam hitungan minggu. Jadikan dokumentasi artifact dari kode, bukan dokumen terpisah yang harus di-maintain manual.

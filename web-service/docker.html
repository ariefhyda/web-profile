Kita sudah punya banyak microservice — masing-masing dengan dependency & versi bahasa berbeda. Bagaimana cara menjalankan semuanya tanpa neraka instalasi? Jawabannya: Container. Sebuah container membungkus aplikasi + semua dependency-nya menjadi satu paket yang berjalan identik di laptop Anda, di server staging, dan di production cloud. Docker adalah implementasi container yang paling populer.

🚢
Analogi: Kontainer Kapal

Sebelum container shipping ditemukan, setiap barang dikemas berbeda — keramik dengan jerami, anggur di kayu, mesin di crate. Bongkar-muat = mimpi buruk. Setelah container standar hadir: semua dimuat ke kontainer 20-feet yang sama, crane mengangkut tanpa peduli isinya. Itulah esensi Docker — standarisasi cara membungkus & menjalankan aplikasi.

Dockerfile — Membungkus Aplikasi Node.js

Dockerfile (single-stage, sederhana) 
# Base image — pilih versi tag spesifik (jangan 'latest')
FROM node:20-alpine

# Buat folder kerja di dalam container
WORKDIR /app

# Copy manifest dulu — agar 'npm install' bisa cache layer
COPY package*.json ./
RUN npm ci --only=production

# Copy sisa source code
COPY . .

# Expose port (informatif, untuk dokumentasi)
EXPOSE 3000

# Perintah default saat container dijalankan
CMD ["node", "server.js"]

Multi-Stage Build — Image yang Lebih Ramping

Dependency build (TypeScript compiler, Webpack) tidak diperlukan saat runtime. Multi-stage build membuat dua tahap: tahap build (gemuk, dengan toolchain), tahap runtime (ringan, hanya artefak hasil build).

Dockerfile (multi-stage, production-grade) 
# ===== Stage 1: Build =====
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# ===== Stage 2: Runtime — minimal =====
FROM node:20-alpine
WORKDIR /app

# Non-root user untuk keamanan
RUN addgroup -S app && adduser -S app -G app
USER app

COPY --from=builder --chown=app:app /app/dist ./dist
COPY --from=builder --chown=app:app /app/node_modules ./node_modules
COPY --from=builder --chown=app:app /app/package.json ./

EXPOSE 3000
HEALTHCHECK --interval=30s --timeout=3s \
  CMD wget -q -O- http://localhost:3000/health || exit 1

CMD ["node", "dist/server.js"]

Docker Compose — Mengorkestra Banyak Service

Docker Compose mendeskripsikan stack multi-container di satu file YAML. Cocok untuk development environment yang butuh API + database + cache + message broker sekaligus. Sekali docker compose up → semua siap.

docker-compose.yml — full microservices stack 
services:
  # --- Database ---
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: kampus
      POSTGRES_USER: app
      POSTGRES_PASSWORD: secret
    volumes:
      - pgdata:/var/lib/postgresql/data
    ports: ["5432:5432"]

  # --- Message Broker ---
  rabbitmq:
    image: rabbitmq:3-management-alpine
    ports: ["5672:5672", "15672:15672"]  # AMQP + UI

  # --- API Service (Mahasiswa) ---
  mahasiswa-api:
    build: ./services/mahasiswa
    environment:
      DB_HOST: postgres      # pakai nama service sebagai hostname
      DB_NAME: kampus
      AMQP_URL: amqp://rabbitmq:5672
    depends_on: [postgres, rabbitmq]
    ports: ["3001:3000"]

  # --- API Service (Nilai) ---
  nilai-api:
    build: ./services/nilai
    environment:
      DB_HOST: postgres
      AMQP_URL: amqp://rabbitmq:5672
    depends_on: [postgres, rabbitmq]
    ports: ["3002:3000"]

  # --- API Gateway (NGINX) ---
  gateway:
    image: nginx:alpine
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
    depends_on: [mahasiswa-api, nilai-api]
    ports: ["8080:80"]

volumes:
  pgdata:
terminal 
# Bangun semua image & start stack
docker compose up -d --build

# Lihat status
docker compose ps

# Tail log salah satu service
docker compose logs -f mahasiswa-api

# Stop & hapus semua (volume dipertahankan)
docker compose down

# Stop & hapus semua TERMASUK volume (HATI-HATI: data hilang)
docker compose down -v

Compose otomatis: (1) membuat jaringan privat kampus_default tempat semua service saling kenal via nama, (2) mengelola dependency start order, (3) menyatukan volume.

Praktik Terbaik Production

  1. Pakai versi tag spesifik — node:20.11-alpine, bukan node:latest. latest bisa berubah diam-diam.
  2. Image sekecil mungkin — Alpine/distroless lebih kecil & lebih sedikit CVE. Multi-stage build untuk buang dependency build.
  3. Jangan jalankan sebagai root — Buat user khusus dengan USER di Dockerfile.
  4. Konfigurasi via environment variable — Jangan hard-code DB credential di image. Pakai .env file di luar.
  5. Tambahkan HEALTHCHECK — Agar orchestrator (Kubernetes, Swarm) tahu container Anda sehat.
  6. Stateless container — Jangan menyimpan data penting di filesystem container; pakai volume / external DB.
  7. Cache layer dengan urutan benar — Copy package.json lalu install dependency sebelum copy source code. Build berikutnya jadi cepat saat source berubah tapi dependency tidak.
  8. Scan vulnerability — Pakai docker scout cves atau Trivy untuk cek CVE sebelum push ke production.

Di Atas Docker Compose: Kubernetes

Compose hebat untuk development & deployment kecil. Untuk produksi skala besar yang butuh self-healing, autoscaling, rolling update, dan multi-node — Anda akan naik level ke Kubernetes (k8s). Konsepnya mirip: Pod (≈ container), Deployment (set pod), Service (load balancer), Ingress (gateway). Banyak proyek menulis manifest k8s sejajar dengan docker-compose.yml dev.

Roadmap Singkat

Mulai dari: Docker (1 container) → Docker Compose (multi-service dev) → Kubernetes (production scale). Tidak harus loncat ke k8s langsung — kompleksitasnya besar. Compose sering cukup untuk staging dan deployment kecil (VPS, single VM).

Tantangan Take-home

(1) Buat Dockerfile multi-stage untuk project Laravel REST API Anda (Pertemuan 5). (2) Susun docker-compose.yml yang menjalankan: aplikasi Laravel + MySQL + Redis + Nginx. (3) Tambahkan healthcheck di tiap service.

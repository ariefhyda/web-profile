Apa itu Web Service?

Web service adalah perangkat lunak yang dirancang untuk mendukung pertukaran data antar aplikasi melalui jaringan, biasanya menggunakan protokol HTTP. Berbeda dengan halaman web yang ditujukan untuk dibaca manusia, web service ditujukan untuk dikonsumsi oleh aplikasi lain — entah itu aplikasi mobile, website, perangkat IoT, atau bahkan service lain di belakang layar.

Bayangkan aplikasi mobile Gojek. Saat Anda memesan ojek, aplikasi tidak menghitung tarif sendiri di HP Anda. Aplikasi mengirim permintaan ke server Gojek, server menghitung jarak & tarif, lalu mengembalikan jawabannya dalam bentuk data terstruktur (biasanya JSON). Yang berbicara di tengah itulah web service.

🍽️
Analogi: Pelayan Restoran

Anda (klien) tidak masuk ke dapur untuk masak sendiri. Anda hanya pesan ke pelayan (web service), pelayan menerjemahkan pesanan ke dapur (server & database), lalu mengantar makanan jadi ke meja Anda. Tidak peduli dapur pakai kompor gas atau kompor listrik — Anda tetap menerima format hidangan yang sama. Itulah abstraksi dan interoperabilitas dalam web service.

Sistem Terdistribusi

Web service lahir dari kebutuhan sistem yang terdistribusi — di mana satu aplikasi besar tidak dijalankan di satu komputer saja, melainkan dipecah menjadi beberapa bagian yang berjalan di server-server berbeda yang saling berkomunikasi melalui jaringan.

  1. Skalabilitas — Beban dapat dibagi ke banyak server. Saat Tokopedia diserbu jutaan pembeli H-1 Lebaran, mereka tinggal menambah server, bukan membangun ulang aplikasi.
  2. Keandalan (Fault Tolerance) — Jika satu server mati, server lain tetap melayani. Sistem secara keseluruhan tidak ikut padam.
  3. Spesialisasi — Setiap bagian bisa ditulis dengan teknologi paling cocok. Service rekomendasi pakai Python (kaya library AI), service pembayaran pakai Java (matang & aman), service mobile API pakai Node.js (cepat).
  4. Kolaborasi Tim — Tim berbeda dapat mengerjakan service berbeda secara paralel tanpa mengganggu satu sama lain.

Evolusi: Monolith → SOA → Microservices

Sebelum web service populer, hampir semua aplikasi dibangun sebagai monolith — satu kode besar, satu deployment, satu database. Web service muncul sebagai jawaban atas masalah monolith ketika aplikasi tumbuh terlalu besar.

Monolith vs SOA — Perbandingan Praktis

Aspek Monolith SOA
Struktur Satu codebase, satu binary/deployment Beberapa service yang berkomunikasi via ESB / message bus
Database Satu database bersama untuk semua modul Boleh berbagi, tapi service punya kontrak data sendiri
Bahasa Pemrograman Seragam (umumnya satu bahasa) Bebas — tiap service bisa beda bahasa selama patuh kontrak
Deployment Ganti 1 baris kode → deploy ulang seluruh aplikasi Deploy per service secara independen
Skalabilitas Skala vertikal (perbesar server) Skala horizontal per service yang ramai
Kompleksitas Awal Rendah, cepat dimulai Tinggi — perlu desain kontrak & bus komunikasi
Cocok Untuk Startup / MVP / aplikasi kecil-menengah Enterprise besar dengan banyak sistem warisan

Karakteristik Inti Sebuah Web Service

  1. Berbasis Standar Terbuka — Menggunakan protokol & format yang disepakati industri (HTTP, JSON, XML), bukan format tertutup vendor.
  2. Loose Coupling — Klien dan server hanya terikat pada kontrak/interface, bukan pada detail implementasi. Bahasa server boleh berubah selama kontrak sama.
  3. Self-Contained — Setiap permintaan membawa cukup informasi untuk diproses; server tidak perlu mengingat sesi sebelumnya (terutama untuk REST).
  4. Dapat Ditemukan (Discoverable) — Disertai dokumentasi atau metadata (Swagger/OpenAPI, WSDL) agar developer lain tahu cara memakainya.
  5. Interoperabilitas — Bisa dipanggil dari Flutter, React, PHP, Python, perangkat IoT — apa pun yang bisa mengirim request HTTP.

Contoh Konkret: Sebuah Response Web Service

Berikut contoh ketika aplikasi mobile meminta data profil user id=12 ke web service. Server merespons dengan dokumen JSON yang ringkas, mudah diparse oleh aplikasi mana pun:

GET /api/users/12 — Response 200 OK 
{
  "id": 12,
  "name": "Arif Hidayah",
  "role": "dosen",
  "profile": {
    "email": "hyda.arif@gmail.com",
    "campus": "Politeknik Harapan Bersama"
  },
  "courses": ["Data Mining", "Web Service", "Mobile Programming"]
}

Aplikasi yang menerima JSON ini bisa langsung memetakan data ke layar, terlepas dari bahasa pemrograman aplikasi tersebut. Inilah kekuatan utama interoperabilitas.

Alur Request & Response

Klien mobile meminta GET /api/users/12. Klik Jalankan untuk melihat perjalanan request hingga JSON kembali ke layar.

1
Klien membentuk HTTP request
Aplikasi mobile menyusun GET ke URL endpoint, lengkap dengan header (Authorization, Accept).
2
Request melintasi jaringan
Lewat internet/WiFi, ditangani DNS → IP server → port 443 (HTTPS).
3
Server menerima & routing
Web service mencocokkan URL /api/users/{id} ke handler yang sesuai.
4
Handler memproses logika
Validasi token, ambil data dari database, susun objek user.
5
Response JSON dikirim balik
Status 200 OK + body JSON melalui koneksi yang sama.
6
Klien merender ke UI
Mobile mem-parse JSON dan menampilkan profil user di layar.

Mengapa Interoperabilitas itu Penting?

Dalam dunia nyata, satu perusahaan jarang menggunakan satu teknologi saja. Bank tradisional masih menjalankan sistem inti di COBOL, tim mobile-nya pakai Flutter, tim data pakai Python, dan tim website pakai JavaScript. Tanpa web service, sistem-sistem ini akan berdiri sendiri dan tidak bisa berbicara satu sama lain.

Manfaat Interoperabilitas

Sistem warisan tetap berjalan, sistem baru tetap modern, dan keduanya bertukar data lewat kontrak web service. Tidak perlu merombak semuanya sekaligus — investasi puluhan tahun tidak menjadi sia-sia.

Apa yang Akan Dipelajari di Mata Kuliah Ini?

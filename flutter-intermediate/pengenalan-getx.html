Modul 2: Pengenalan GetX

Estimasi: 50 Menit
Teori & Demo

GetX adalah package Flutter buatan Jonny Borges yang menggabungkan tiga kebutuhan utama aplikasi modern dalam satu paket: State Management, Route Management, dan Dependency Injection. Tagline-nya: "Open Source, Performant, Productive".

🛠️
Analogi: Swiss Army Knife

Bayangkan harus selalu bawa 3 alat: pisau (state management), obeng (routing), tang (DI). GetX = pisau lipat Swiss Army — satu alat, semua fungsi tersedia. Hemat tempat di tas (project), hemat berat (dependency), dan API-nya konsisten.

Filosofi GetX

  1. Productivity — kode pendek, sintaks intuitif. Aksi yang biasanya 10 baris cukup 1 baris.
  2. Performance — minimal overhead. State management-nya bahkan tidak butuh BuildContext.
  3. Organization — pisahkan View dari Business Logic dengan mudah, tanpa boilerplate.
  4. All-in-one — tidak perlu campur banyak package (Provider + Get_it + auto_route). Satu GetX cukup.

Mengapa GetX Populer di Indonesia?

Sintaks ringkas + CLI scaffolding + komunitas Indonesia yang aktif. Banyak channel YouTube Indonesia (Erico Darmawan, Programmer Zaman Now, dll) yang mengangkat GetX. Cocok untuk freelance & startup yang butuh delivery cepat.

Hello World GetX

Berikut contoh paling sederhana: counter app dengan GetX. Bandingkan dengan setState.

😐 Cara setState (klasik)
class Counter extends StatefulWidget {
  final _State createState() => _State();
}

class _State extends State<Counter> {
  int count = 0;

  void tambah() {
    setState(() {
      count++;
    });
  }

  @override
  Widget build(_) {
    return Scaffold(
      body: Text('$count'),
      floatingActionButton: FAB(
        onPressed: tambah,
      ),
    );
  }
}
✨ Cara GetX (ringkas)
// 1. Controller terpisah
class CounterController extends GetxController {
  final count = 0.obs; // Reactive!
  void tambah() => count++;
}

// 2. View — StatelessWidget!
class Counter extends StatelessWidget {
  final c = Get.put(CounterController());

  @override
  Widget build(_) {
    return Scaffold(
      body: Obx(() => Text('${c.count}')),
      floatingActionButton: FAB(
        onPressed: c.tambah,
      ),
    );
  }
}
Tiga Keuntungan Langsung

1. Tidak butuh StatefulWidget lagi — StatelessWidget cukup. 2. Logic dipisah ke Controller — bisa dites, bisa dipakai ulang. 3. setState() hilang — tinggal Obx() di tempat yang perlu rebuild.

Instalasi GetX

Tambahkan dependency di pubspec.yaml lalu jalankan flutter pub get:

pubspec.yaml 
dependencies:
  flutter:
    sdk: flutter
  get: ^4.6.6   # versi stabil terbaru

Lalu di main.dart, ganti MaterialApp dengan GetMaterialApp agar fitur routing GetX aktif:

main.dart 
import 'package:flutter/material.dart';
import 'package:get/get.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return GetMaterialApp(   // 👈 bukan MaterialApp lagi
      title: 'My App',
      home: HomePage(),
    );
  }
}

Snackbar, Dialog, BottomSheet — Tanpa Context!

Salah satu fitur GetX yang paling disukai: tampilkan UI overlay tanpa harus pegang BuildContext. Cocok dipanggil dari Controller.

Dart 
// Snackbar
Get.snackbar('Sukses', 'Data tersimpan!');

// Snackbar dengan kustom
Get.snackbar(
  'Error',
  'Login gagal',
  backgroundColor: Colors.red,
  snackPosition: SnackPosition.BOTTOM,
);

// Dialog
Get.defaultDialog(
  title: 'Konfirmasi',
  middleText: 'Hapus item ini?',
  textConfirm: 'Ya',
  textCancel: 'Batal',
  onConfirm: () => deleteItem(),
);

// Bottom Sheet
Get.bottomSheet(
  Container(
    color: Colors.white,
    child: Column(...),
  ),
);

// Navigasi (lihat Modul 6 untuk detail)
Get.to(DetailPage()); // push
Get.back();           // pop
Get.off(LoginPage()); // replace

Kekurangan GetX (Jujur)

  1. "Magic" — fitur otomatisnya kadang sulit di-debug saat ada bug.
  2. Dependency tunggal — kalau GetX bermasalah, banyak hal terdampak.
  3. Bukan standar resmi Flutter team — beberapa proyek korporat lebih suka Provider/Bloc/Riverpod.
  4. Hot reload kadang lebih lambat dibanding Provider untuk reactive state.
  5. Komunitas global lebih kecil dari Provider/Bloc — meski di Indonesia justru sebaliknya.
Tetap Belajar Multiple Tools

Walaupun course ini fokus ke GetX, jangan stuck di satu solusi. Setelah lulus, eksplor juga Riverpod (penerus Provider yang modern) dan Bloc (jika ingin masuk perusahaan besar). Skill yang fleksibel = lebih marketable.

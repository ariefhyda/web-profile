Modul 4: GetX CLI & Scaffolding

Estimasi: 40 Menit
Praktikum

Bayangkan tiap kali bikin fitur baru harus: bikin folder, bikin 3 file (view, controller, binding), import package, daftar di routes... capek! GetX CLI mengotomatisasi semua itu — ketik 1 perintah, dapat folder lengkap. Hemat 5-10 menit per fitur.

🍔
Analogi: McDonald's vs Masak Sendiri

Mau makan burger? Bisa beli bahan, racik, panggang, plating sendiri (manual scaffolding). Atau langsung ke McD — pesan, 3 menit jadi (GetX CLI). Hasilnya: burger yang konsisten setiap kali. GetX CLI = scaffolding instan dengan struktur konsisten.

Instalasi GetX CLI

GetX CLI adalah global package Dart — perlu install satu kali per komputer.

Terminal 
# Install global
dart pub global activate get_cli

# Verifikasi instalasi
get --version
# Output: get_cli vX.X.X

# Jika error "command not found", tambahkan ke PATH:
# macOS/Linux: export PATH="$PATH:$HOME/.pub-cache/bin"
# Windows: tambahkan %LOCALAPPDATA%\Pub\Cache\bin ke PATH

Perintah-perintah Penting

1. get init — Inisialisasi Proyek

Setup struktur folder GetX di proyek Flutter yang sudah ada. Wajib jalankan sekali sebelum perintah lain.

terminal 
# Di dalam folder proyek Flutter
get init

# CLI akan tanya:
# - Mau pakai GetMaterialApp? (y/n)
# - Setup struktur folder? (y/n)

# Hasilnya: folder app/, routes/, modules/ otomatis terbuat

2. get create page:nama — Buat Halaman Lengkap

Generate 1 module lengkap (folder + 3 file: view, controller, binding) sekaligus daftarkan ke app_pages.dart.

terminal 
# Buat halaman Login
get create page:login

# Output: file-file berikut otomatis dibuat
# ├── lib/app/modules/login/
# │   ├── bindings/login_binding.dart
# │   ├── controllers/login_controller.dart
# │   └── views/login_view.dart
# └── lib/app/routes/app_pages.dart (auto-update)

# Buat halaman dengan sub-folder
get create page:profile/edit-profile

3. get create controller:nama

terminal 
# Tambah controller ke module yang sudah ada
get create controller:auth on home

# Output: lib/app/modules/home/controllers/auth_controller.dart

4. get create model:nama

terminal 
# Generate Model dari JSON (otomatis fromJson + toJson)
get create model:user on home with assets/user.json

# Atau model kosong
get create model:user

5. get create provider:nama

Generate kelas Provider (HTTP client / API service):

terminal 
get create provider:product

# Output: lib/app/data/providers/product_provider.dart
# Berisi ConnectService class dengan method GET/POST/PUT/DELETE

Workflow Pengembangan Tipikal

Berikut alur kerja sehari-hari pakai GetX CLI:

Step 1
Buat project Flutter & install GetX
flutter create my_app && cd my_app && flutter pub add get
Step 2
Inisialisasi struktur GetX
get init — generate folder app/, routes/, dll.
Step 3
Buat halaman pertama
get create page:home — view + controller + binding + auto register route.
Step 4
Tambah model & provider
get create model:user + get create provider:user
Step 5
Tulis logic di Controller, UI di View
Buka file yang sudah di-generate, isi sesuai kebutuhan fitur.
Step 6
Halaman lanjutan
get create page:detail, get create page:profile, dst. Konsisten dengan cepat!

Contoh: Buat 4 Halaman dalam 30 Detik

Tanpa CLI, ini butuh bikin folder + 12 file + register route manual = ~30 menit. Dengan CLI: 4 baris perintah.

terminal — workflow real 
# Setup awal
flutter create blog_app
cd blog_app
flutter pub add get
get init

# 4 halaman dalam 4 perintah
get create page:home
get create page:detail
get create page:login
get create page:profile

# Model + provider untuk data
get create model:post
get create model:user
get create provider:post

# Total: 7 perintah → struktur project lengkap! 🚀
Konsistensi = Kekuatan

Manfaat tersembunyi CLI: konsistensi. Semua module punya struktur sama, naming sama, import sama. Saat tim Anda lihat fitur baru, mereka langsung tahu di mana file mana. Tidak ada "ah, fitur ini beda strukturnya karena dibuat sebelum kita standardisasi".

Trouble Shooting

⚠ "get: command not found"

Penyebab: PATH belum ter-set ke folder pub-cache.
Solusi (macOS/Linux): Tambahkan ke ~/.zshrc atau ~/.bashrc:
export PATH="$PATH:$HOME/.pub-cache/bin"
Solusi (Windows): Add ke Environment Variables: %LOCALAPPDATA%\Pub\Cache\bin

⚠ "Invalid pubspec.yaml"

CLI biasanya error kalau project Flutter belum punya get di dependencies. Jalankan flutter pub add get dulu sebelum get init.

⚠ "Module already exists"

CLI tidak akan overwrite file yang sudah ada (safety feature). Jika ingin reset, hapus folder module-nya manual lalu jalankan ulang. Atau pakai nama berbeda.

Modul 7: Dependency Injection (DI)

Estimasi: 50 Menit
Teori & Demo

Dependency Injection (DI) adalah pola di mana sebuah class menerima dependency-nya dari luar — bukan membuatnya sendiri. GetX menyediakan service locator built-in: Get.put(), Get.lazyPut(), dan Get.find(). Tidak perlu singleton manual, tidak perlu global variable.

🚿
Analogi: Kran Air

Bayangkan rumah tanpa pipa air — setiap kamar harus bikin sumur sendiri. Boros, ribet. DI = pipa air pusat (Get). Semua kamar (controller) tinggal buka kran (Get.find) — airnya datang. Mau ganti sumber air? Cukup ganti di satu tempat (Get.put).

Mengapa Butuh DI?

❌ Tanpa DI (tight coupling)
class ProductController {
  // 👇 Bikin sendiri = bermasalah
  final repo = ProductRepository();
}

class CartController {
  // 👇 Bikin lagi instance baru!
  final repo = ProductRepository();
}

// 🚨 2 instance berbeda
// 🚨 Sulit dites (tidak bisa mock)
// 🚨 Boros memory & API call
✅ Dengan DI (loose coupling)
// Daftar 1x
Get.put(ProductRepository());

class ProductController {
  // 👇 Cari instance yang sudah ada
  final repo = Get.find<ProductRepository>();
}

class CartController {
  // 👇 Instance yang SAMA
  final repo = Get.find<ProductRepository>();
}

// 🎉 1 instance, dipakai berdua
// 🎉 Bisa di-mock untuk testing
// 🎉 Hemat memory & cache

3 Method Utama DI di GetX

MethodKapan DibuatLifecycleUse Case
Get.put(X())Langsung (eager)Dihapus saat halaman ditutup (jika di Binding)Controller halaman aktif
Get.put(X(), permanent: true)LangsungHidup sampai app matiAuthService, ThemeService
Get.lazyPut(() => X())Saat dipanggil pertama kaliDihapus saat tidak dipakaiResource berat yang tidak selalu dipakai

Pola Penggunaan Tipikal

1. AuthService — Permanent (dipakai sepanjang app)

main.dart 
void main() async {
  WidgetsFlutterBinding.ensureInitialized();

  // Service yang dipakai SEPANJANG app — permanent
  Get.put(AuthService(),  permanent: true);
  Get.put(ThemeService(), permanent: true);

  // Service async (perlu await init)
  await Get.putAsync(() async {
    final service = StorageService();
    await service.init();
    return service;
  });

  runApp(MyApp());
}

2. Controller via Binding (per route)

home_binding.dart 
class HomeBinding extends Bindings {
  @override
  void dependencies() {
    // Repository — lazyPut, dibuat saat pertama dipanggil
    Get.lazyPut(() => ProductRepository());

    // Controller — pakai Get.find untuk inject repository
    Get.lazyPut(() => HomeController(
      repository: Get.find<ProductRepository>(),
    ));
  }
}

// Saat /home dibuka → dependencies() jalan
// Saat /home ditutup → dependency dihapus dari memory

3. Akses dari Controller / Service Lain

akses dependency 
class CartController extends GetxController {
  // Cara 1: di property — Get.find dijalankan saat instance dibuat
  final AuthService _auth = Get.find<AuthService>();

  // Cara 2: di method (lebih flexible)
  void checkout() {
    final auth = Get.find<AuthService>();
    if (!auth.isLoggedIn) {
      Get.toNamed('/login');
      return;
    }
    // ... lanjut checkout
  }
}

// Helper shortcut — kalau hanya 1 instance
final auth = Get.find<AuthService>();
// Setara dengan: Get.find<AuthService>(tag: null)

// Beberapa instance dengan tag
Get.put(ApiClient('prod'), tag: 'prod');
Get.put(ApiClient('staging'), tag: 'staging');
final stagingApi = Get.find<ApiClient>(tag: 'staging');

Get.put vs lazyPut — Kapan Pakai Apa?

SkenarioRekomendasiAlasan
Service global (Auth, Theme)put(permanent: true)Dipakai sepanjang app
Controller halaman aktiflazyPut di BindingHanya saat halaman aktif
Resource berat & jarang dipakailazyPutHanya dibuat jika perlu
Init async (Hive, SharedPreferences)putAsyncBisa await init
State per-form (registrasi)createInstance segar tiap dipanggil

GetxService vs GetxController

GetX punya dua tipe class untuk DI: GetxController (dihapus saat tidak dipakai) dan GetxService (tidak pernah dihapus, kecuali manual). Pilih sesuai kebutuhan.

📦 GetxController
class ProductController extends GetxController {
  final products = <Product>[].obs;

  // Hidup hanya saat halaman aktif
  // Auto-deleted saat halaman ditutup
}

// Daftarkan di Binding
Get.lazyPut(() => ProductController());
🌟 GetxService
class ApiClient extends GetxService {
  Future<ApiClient> init() async {
    // init logic
    return this;
  }

  // Hidup selama app jalan
  // Tidak akan dihapus Get.delete()
}

// Daftarkan di main()
await Get.putAsync(() => ApiClient().init());

Testing dengan DI (Bonus)

Salah satu keuntungan terbesar DI: kemudahan testing. Anda bisa mock service untuk unit test.

test/home_controller_test.dart 
import 'package:flutter_test/flutter_test.dart';
import 'package:get/get.dart';
import 'package:mockito/mockito.dart';

class MockProductRepo extends Mock implements ProductRepository {}

void main() {
  test('HomeController loads products', () async {
    final mockRepo = MockProductRepo();
    when(mockRepo.getAll()).thenAnswer((_) async => [Product(...)]);

    // Inject mock
    Get.put<ProductRepository>(mockRepo);

    final controller = HomeController(repository: mockRepo);
    await controller.loadProducts();

    expect(controller.products.length, 1);
  });
}

Best Practices

  1. Daftarkan service global di main() dengan permanent: true. Contoh: AuthService, ThemeService, ApiClient.
  2. Pakai Binding untuk controller halaman. GetX akan auto-cleanup saat halaman ditutup.
  3. Pakai lazyPut kalau ragu. Resource hanya dibuat jika benar-benar dipakai = hemat memory & startup time.
  4. Inject lewat constructor (bukan Get.find di property) saat butuh testable code. Membuat dependency eksplisit.
  5. Hindari Get.find di build(). Panggil di onInit() controller atau di constructor — bukan di setiap rebuild widget.
"Get.find raised an Exception"

Error paling umum. Penyebab: panggil Get.find<X>() sebelum X di-put(). Solusinya: pastikan di-put dulu (di main, binding, atau dalam initState parent widget). Cek juga apakah Binding sudah di-attach ke route.

Modul 2: Arsitektur Docker

Estimasi: 35 Menit
Teori & Konsep

Docker memakai arsitektur client–server. Saat Anda mengetik perintah docker di terminal, Anda sebenarnya hanya menggunakan client yang mengirim instruksi ke sebuah program server yang bekerja di latar belakang. Memahami pembagian peran ini adalah kunci untuk tidak bingung ketika sesuatu tidak berjalan.

1. Komponen Utama

  1. Docker Client (CLI) — Perintah docker run, docker pull, dsb. Client menerjemahkan perintah Anda menjadi panggilan REST API dan mengirimnya ke daemon.
  2. Docker Daemon (dockerd) — "Otak" Docker yang berjalan sebagai background service. Ia membangun image, menjalankan container, mengatur network & volume. Client dan daemon berkomunikasi lewat socket atau jaringan.
  3. Docker Images — Penyimpanan image hasil build atau pull, tersimpan lokal di host.
  4. Docker Containers — Instance image yang sedang berjalan, dikelola sepenuhnya oleh daemon.
  5. Registry — Server penyimpanan image jarak jauh, seperti Docker Hub. Daemon menarik (pull) atau mendorong (push) image ke sini.
Poin Penting

Client tidak pernah menjalankan container secara langsung. Ia hanya "menitipkan perintah" ke daemon. Itulah mengapa jika service dockerd mati, semua perintah docker akan gagal walau aplikasinya benar.

2. Simulasi Alur Perintah

Pilih salah satu perintah di bawah. Amati bagaimana instruksi mengalir antar komponen — dari Client, ke Daemon, mungkin ke Registry, lalu menjadi Container. Panel log akan menjelaskan tiap langkah secara berurutan.

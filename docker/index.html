Selamat datang di kelas Docker. Sebelum menyentuh perintah teknis, kita perlu memahami masalah apa yang sebenarnya ingin dipecahkan oleh Docker. Pemahaman ini akan membuat seluruh modul berikutnya terasa jauh lebih masuk akal.

1. Masalah Klasik: "It Works on My Machine"

Pernahkah Anda membuat aplikasi yang berjalan sempurna di laptop sendiri, tetapi error saat dijalankan di komputer teman atau di server? Penyebabnya hampir selalu sama: perbedaan environment — versi bahasa pemrograman berbeda, library yang hilang, konfigurasi sistem operasi tidak sama, atau variabel lingkungan yang lupa di-set.

Inti Persoalan

Aplikasi tidak hidup sendirian. Ia bergantung pada dependency dan environment di sekelilingnya. Docker menyatukan aplikasi beserta seluruh dependensinya ke dalam satu paket terstandar yang dijamin berjalan sama di mana pun — laptop dosen, laptop mahasiswa, maupun server produksi.

2. Apa itu Docker?

Docker adalah platform open-source untuk membangun, mengirim, dan menjalankan aplikasi di dalam unit terisolasi yang ringan dan portabel bernama container (kontainer). Analogi paling populer datang dari dunia logistik: sebelum ada peti kemas standar, memuat barang ke kapal sangat rumit karena bentuk barang berbeda-beda. Setelah ada peti kemas (container) standar, apa pun isinya, cara mengangkut dan menumpuknya jadi seragam.

Docker membawa ide yang sama ke dunia software: apa pun bahasa atau framework aplikasi Anda (PHP, Python, Node.js, Java), setelah dikemas menjadi container, cara menjalankannya selalu sama.

3. Tiga Istilah Kunci

  1. Image — Cetak biru (blueprint) aplikasi: berisi kode, runtime, library, dan konfigurasi. Bersifat read-only, mirip "file installer" atau "resep masakan".
  2. Container — Hasil menjalankan sebuah image. Ini adalah instance aktif aplikasi yang sedang berjalan. Dari satu image bisa lahir banyak container, layaknya banyak kue dari satu resep.
  3. Registry — Gudang penyimpanan image (misalnya Docker Hub), tempat kita mengunduh (pull) atau mengunggah (push) image agar bisa dibagikan.

4. Container vs Virtual Machine (VM)

Banyak yang mengira container itu sama dengan Virtual Machine. Keduanya memang sama-sama mengisolasi aplikasi, tetapi cara kerjanya sangat berbeda. VM memvirtualisasikan perangkat keras sehingga setiap VM membawa Guest OS-nya sendiri yang berat. Sementara container memvirtualisasikan sistem operasi — semua container berbagi kernel Host OS yang sama melalui Docker Engine, sehingga jauh lebih ramping.

Geser jumlah aplikasi pada simulasi di bawah, lalu amati bagaimana tumpukan (stack), total ukuran, dan waktu startup berubah drastis antara kedua pendekatan.

Bukan Saling Menggantikan

Container tidak selalu menggantikan VM. Keduanya sering dipakai bersama: container dijalankan di dalam VM di lingkungan cloud untuk menggabungkan isolasi keras VM dengan efisiensi container.

5. Mengapa Mahasiswa Perlu Belajar Docker?

Keuntungan

  • Konsisten — hilang sudah alasan "di laptop saya jalan kok".
  • Cepat di-setup — environment kompleks siap dalam hitungan detik.
  • Ringan — bisa menjalankan banyak service di satu laptop.
  • Skill industri — standar wajib di dunia DevOps & cloud.

Tantangan

  • Kurva belajar konsep baru (image, layer, volume).
  • Perlu pembiasaan dengan antarmuka command line.
  • Keamanan & networking butuh perhatian ekstra di produksi.

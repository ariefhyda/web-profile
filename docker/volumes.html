Modul 6: Volume & Persistensi Data

Estimasi: 40 Menit
Praktikum

Container itu bersifat ephemeral (sementara). Semua perubahan file yang ditulis di dalam container disimpan pada writable layer-nya — dan lapisan itu ikut terhapus begitu container dihapus. Untuk data yang harus tetap ada (database, file upload), kita memakai Volume.

1. Tiga Cara Menyimpan Data

  1. Writable layer container — Default. Cepat hilang saat container di-rm. Cocok hanya untuk data sementara.
  2. Volume — Penyimpanan yang dikelola Docker (docker volume create), terpisah dari siklus hidup container. Cara yang direkomendasikan untuk data persisten.
  3. Bind mount — Memetakan folder asli di host ke dalam container. Berguna saat development agar perubahan kode langsung terlihat.

2. Simulasi: Hilang vs Bertahan

Pilih mode, tulis beberapa file, lalu klik "Hapus & buat ulang container". Bandingkan apa yang terjadi pada data saat container yang sama dibuat ulang — tanpa volume versus dengan volume.

3. Perintah Volume

terminal 
# Membuat named volume
docker volume create appdata

# Menjalankan container dengan volume (named volume)
docker run -d -v appdata:/app/data myapp

# Bind mount: petakan folder host ke container (cocok untuk dev)
docker run -d -v $(pwd):/app myapp

Modul 7: Docker Networking

Estimasi: 40 Menit
Teori & Praktikum

Secara default, container terisolasi dalam jaringan internal Docker. Agar bisa diakses dari luar (browser di host Anda), port container harus dipublikasikan ke port host menggunakan flag -p HOST:CONTAINER. Memahami arah pemetaan ini adalah sumber kebingungan nomor satu bagi pemula.

1. Tipe Network Driver

DriverKarakteristik
bridgeDefault. Jaringan privat di host; butuh -p untuk akses dari luar.
hostContainer memakai langsung network host (tanpa isolasi port).
noneTanpa jaringan sama sekali (terisolasi penuh).
overlayMenghubungkan container antar host berbeda (untuk Swarm/cluster).

2. Simulasi Port Mapping

Container menjalankan nginx yang listen di port 80. Atur apakah port dipublikasikan, tentukan port host, lalu coba akses localhost:<port> dari "browser". Amati apakah request berhasil diteruskan atau ditolak.

Cara Membaca -p 8080:80

Angka kiri = port di host (yang Anda ketik di browser). Angka kanan = port di dalam container (tempat aplikasi listen). Jadi -p 8080:80 berarti "akses localhost:8080 di host akan diteruskan ke port 80 container".

3. Komunikasi Antar Container

Pada user-defined bridge network, container dapat saling memanggil cukup dengan nama container sebagai hostname (Docker menyediakan DNS internal). Inilah dasar bagaimana service api terhubung ke db tanpa perlu tahu alamat IP-nya.

terminal 
# Buat network sendiri
docker network create app-net

# Jalankan db & api di network yang sama
docker run -d --name db --network app-net postgres
docker run -d --name api --network app-net myapi

# Di dalam container api, host "db" otomatis resolve ke container db
# mis. koneksi ke: postgres://db:5432

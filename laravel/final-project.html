Skripsi Mini

Tema Proyek: Mini Blog CMS

Bangun sistem Content Management System (CMS) atau aplikasi blog sederhana — mirip Medium atau Dev.to dalam skala kecil. Aplikasi ini punya 2 sisi: halaman publik (pembaca) dan dashboard (penulis).

Tech Stack Wajib

Backend: Laravel 10 atau 11
Database: MySQL / MariaDB / PostgreSQL / SQLite
Frontend: Blade + Tailwind CSS atau Bootstrap 5
Auth: Laravel Breeze (boleh manual jika ingin lebih custom)

📦 Setup & Persiapan

  • Project Laravel baru di-create + connect database
  • Install Breeze — login, register, dashboard sudah jalan
  • Repository Git dibuat + push initial commit
  • Tailwind/Bootstrap ter-compile (Vite npm run dev jalan)

🗄️ Database & Model

  • Migration posts (title, slug, body, thumbnail, user_id, category_id)
  • Migration categories (name, slug)
  • Relasi User-hasMany-Posts & Category-hasMany-Posts
  • Seeder: 1 admin + 3 user + 5 kategori + 20 post dummy
  • Kolom role di users (enum: admin, user)
  • (Bonus) Tabel tags + pivot post_tag (many-to-many)

🔐 Auth & Authorization

  • Login, register, logout sudah jalan
  • Middleware auth proteksi route /dashboard/*
  • Middleware/Policy: hanya owner yang bisa edit/hapus post-nya
  • Admin bisa kelola semua post & semua user

📝 Fitur CRUD Posts

  • List post di dashboard (hanya milik user yg login, pagination)
  • Form Create post — validasi (title required, body min 50)
  • Slug otomatis dari title (URL: /post/judul-artikel)
  • Upload thumbnail image — disimpan di storage/app/public/posts
  • Edit & Update post (form pre-filled)
  • Delete post (dengan konfirmasi)

🌐 Halaman Publik

  • Beranda: list semua post terbaru (pagination 9 per halaman)
  • Detail post: judul, body, penulis, kategori, tanggal (diffForHumans)
  • Filter berdasarkan kategori (/category/{slug})
  • Halaman penulis: list post per author (/author/{username})
  • Search post (by title atau body)
  • Layout reusable (<x-layout> atau @extends)

✨ Polish & Submit

  • Halaman responsif (cek di mobile/tablet)
  • Flash message untuk semua aksi (create/update/delete)
  • Error handler kustom 404 & 500
  • README.md jelas (cara install, login admin, screenshot)
  • .env.example include semua key yang dibutuhkan
  • Push final + tag v1.0 ke GitHub
  • Submit URL repo ke platform e-learning

Rubrik Penilaian

AspekBobotKriteria
Fungsionalitas CRUD 30% Semua fungsi jalan tanpa error 500. CRUD lengkap. Pagination. Validasi.
Database & Relasi 25% Migration well-designed (foreign key, default, index). Eloquent relasi dipakai dengan benar (eager loading).
UI / UX 20% Tampilan rapi & responsif. Pakai layout reusable. Flash message. Custom 404.
Keamanan 15% CSRF, validasi input, password hash, policy/authorize, $fillable diatur.
Clean Code 10% Penamaan jelas, kode terstruktur, fitur dipisah jadi controller terpisah, comment seperlunya.

Bonus untuk Nilai A+

  1. Fitur Tag (Many-to-Many): post bisa punya banyak tag
  2. Komentar di setiap post (One-to-Many dengan moderasi admin)
  3. Like / Bookmark sistem (Many-to-Many user-post)
  4. Email Verification aktif (Breeze sudah include)
  5. Markdown Editor untuk body (pakai SimpleMDE atau EasyMDE)
  6. REST API endpoint untuk semua resource (siap dipakai mobile app)
  7. Deploy live ke Vercel/Railway/000webhost — dosen bisa langsung akses
  8. Dark mode toggle dengan persistence (localStorage)
  9. SEO meta tags per post (Open Graph, Twitter Card)
  10. RSS feed untuk artikel terbaru

Tips Sukses

1. Mulai sederhana — fitur dasar dulu, baru polish. 2. Commit kecil & sering ke Git ("commit-driven development"). 3. Test di environment bersih sebelum submit (clone repo + composer install + npm install + migrate). 4. Jangan malu bertanya — tapi search dulu di Google/StackOverflow, jawaban biasanya ada.

Langkah Pengumpulan

  1. Push kode final ke GitHub (pastikan tidak commit vendor/, node_modules/, .env).
  2. Buat README.md berisi: deskripsi project, cara install, kredensial admin default, screenshot, link demo (jika ada).
  3. Tambah .env.example dengan semua key yang dibutuhkan (kosongi nilai sensitif).
  4. Tag rilis final: git tag v1.0 -a -m "Final submission" dan git push --tags.
  5. Submit URL repository ke platform e-learning beserta nama anggota tim.
